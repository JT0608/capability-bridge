## 1. 项目概述

- **产品定位**:能力增强,不是模型替代。"Keep your model. Add what it lacks." 给文本模型(DeepSeek 等)补上视觉能力。
- **一句话**:transport-agnostic 的模型能力桥;MCP 是第一个传输,Vision 是第一个能力。
- **冻结文档**:
  - Spec:`docs/superpowers/specs/2026-08-12-capability-bridge-design.md`(commit `408f2a5`)
  - Plan:`docs/superpowers/plans/2026-08-12-capability-bridge-v0.1.md`(commit `4d30813`,14 个 Task)
- **架构红线(核心约束,由测试强制)**:`core/` 永不 import MCP / 客户端 SDK / 具体 provider / transport;适配器在 core 外实现 `ModelProvider` ABC,依赖向内。

## 2. 执行方式(已与用户约定的治理协议)

- **模式**:Subagent-Driven——每 Task 一个全新 subagent 实现,父代理做 executable review(diff 审查 + 全量 pytest + 架构红线测试),不靠"看像不像计划"。
- **检查点(人工/纵向)**:
  - Task 1–5 Core 契约 ✅ 已过
  - Task 6–10 Provider + Registry + Routing ✅ 已过
  - Task 11–13 完整内部链路 ✅ 已过
  - Task 14 真实产品 E2E ⏳
- **偏差三级**:
  - Level 1(实现细节):subagent 可最小修复,必须记录。
  - Level 2(接口/契约):上收父代理决定。
  - Level 3(架构/产品/范围):立即停止,回冻结 spec 讨论。
- **测试纪律**:不许删测试 / 跳测试 / 降低验收标准;失败先定位修复,过一关进一关;全部完成后跑全量测试。

## 9. Checkpoint 4 验收标准(Task 14)

用户关切:**产品能否兑现 10 条 Product DoD。** 三层验收,层层递进:

```text
A. Automated acceptance(不需要 key)
pytest 全绿(含 setup merge/资源同步单测)、wheel/package resources 正确

B. Clean-machine install acceptance(需要 1 个 key)
uv tool install .(在 repo 内)→ 离开 repo 进空目录 → capability-bridge setup
→ capability-bridge setup --test → 一个 key 首次成功 → run-anywhere

C. Real-user acceptance(需要 key + Claude Code)
Claude Code + DeepSeek 主模型 → MCP → capability-bridge → 真实视觉 Provider → 真看懂一张图片
```

- **RELEASE BLOCKING(发布阻塞)**:单 provider live success(B 层 `--test` 真调通;一个 key 即可证明 "one key → first success")。
- **LIVE HARDENING(不阻塞发布)**:跨 provider 真实 fallback(Provider A 制造 fallback-eligible 失败 → Provider B 真成功)——逻辑已由 Task 10 双 provider fake 测试锁定,缺第二家真实 key **不阻塞 v0.1**;自动化的 fallback 测试仍必须 PASS。
- 真实 E2E 至少两张图:① 普通截图(问"主要区域"→ 验证 image→bridge→provider→DeepSeek 通);② **真实前端截图 + 设计评审 prompt**(视觉层级/间距/字体/配色/一致性/最该改的 3-5 处)→ 验证"视觉推理"命题,而非 caption。
- 若 C 层设计评审只返回"这是一个网页,顶部有导航栏…",**不急着改架构**,按序诊断:trigger 是否正确触发 → DeepSeek 构造的 prompt 质量 → prompt 原样送达(已由 Task 11/13 测试锁死)→ 所选视觉模型的审美能力 → 最后才考虑 capability profile/routing。
- 真实厂商 API 差异一律按 Level 1 最小修复并记录,不反向污染 Core。
